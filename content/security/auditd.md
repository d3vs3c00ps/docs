# auditd

The Linux Audit framework logs system events from the kernel: executions, file
access, system calls. It is the mechanism behind most CIS and STIG audit
requirements, and the thing [[security/selinux]] denials are recorded through.

It is also, if configured carelessly, a reliable way to slow a machine down. Audit
rules are evaluated in the kernel on every matching event, so the cost is paid on the
hot path. Most of this note is therefore about logging *enough* rather than
everything.

## Where the rules live

| Path | What it is |
| --- | --- |
| `/etc/audit/auditd.conf` | daemon configuration — log rotation, disk-full behaviour |
| `/etc/audit/rules.d/*.rules` | rule fragments, the file you actually edit |
| `/etc/audit/audit.rules` | the compiled result, generated by `augenrules` |
| `/usr/share/audit-rules/` | sample rule sets shipped by audit 4.x, including STIG, PCI DSS and OSPP baselines |

Edit fragments under `rules.d/`, then compile and load:

```bash
augenrules --load
auditctl -l          # show the rules currently loaded in the kernel
```

Rules given directly to `auditctl` apply immediately but do not survive a reboot.
Use that for testing, and `rules.d/` for anything permanent.

> [!warning] Correction
> An earlier version said the sample rule sets live in `/usr/share/audit/` and include
> CIS baselines. Since audit 4.0 (RHEL 10, openSUSE Leap 16) they are in
> `/usr/share/audit-rules/`. RHEL 9 (audit 3.x) has them in
> `/usr/share/audit/sample-rules/`. The upstream sets cover STIG, PCI DSS, OSPP and
> NISPOM, not CIS. CIS benchmarks publish their own rules.

On audit 4.x, a separate unit, `audit-rules.service`, runs `augenrules --load` at
boot. openSUSE ships a default `rules.d/audit.rules` with `-a task,never`, which
turns off all syscall auditing. Remove that line before you add syscall rules.

## Rule ordering decides your performance

Audit rules are evaluated **in order, first match wins** — the same model as a
packet filter. The single biggest tuning lever is therefore the order.

Put the events that occur most often at the top, and the exceptions at the bottom.

> [!warning] Alphabetical rule files are a performance bug
> Fragments in `rules.d/` are concatenated in filename order, so a set named
> alphabetically is ordered by accident. Use numeric prefixes (`10-`, `50-`, `99-`)
> and put the exclusions first.

`augenrules` sorts the files with `ls -v` (natural order, so `9-` comes before
`10-`). It also moves the control lines for you: the last `-D`, `-b` and `-f` go to
the top of `audit.rules`, and the last `-e` goes to the very end, whatever file they
are in.

## Excluding what you do not need

The difficulty is logging every important event while not logging the rest. "Log
everything" is a defensible starting point and a bad steady state: it costs kernel
processing time, floods the log, and makes the interesting events harder to find.

Start by measuring what is actually noisy:

```bash
# most events by executable, today only
aureport -ts today -i -x --summary

# most events by system call
aureport -ts today -i -s --summary
```

`-i` resolves numeric IDs into names. `-ts today` limits the window, which matters —
on a busy machine the full log is unusable for this. `aureport` can summarise by
file, user, host and more; `man aureport` lists them.

### Ignoring events

Once you know what is flooding, suppress it. Two keywords:

- **`exclude`** — filters on message type, before the event is generated.
- **`never`** with the `exit` filter — for syscall-based rules.

Suppress all `CWD` (current working directory) records:

```text
-a exclude,always -F msgtype=CWD
```

Because the first match wins, **exclusions must be at the top of the rule set**.

Combine conditions with multiple `-F` expressions — they are ANDed, and you may use
up to 64 of them, though a handful is normally enough. Suppressing the noise from
VMware tools on x86_64, for both the 32-bit and 64-bit syscall tables:

```text
-a exit,never -F arch=b32 -S fork -F success=0 -F path=/usr/lib/vmware-tools -F subj_type=initrc_t -F exit=-2
-a exit,never -F arch=b64 -S fork -F success=0 -F path=/usr/lib/vmware-tools -F subj_type=initrc_t -F exit=-2
```

> [!note] Test every rule you write
> Field availability and syscall numbering differ between kernel versions, so a rule
> copied from elsewhere may silently match nothing. A rule that never fires is pure
> cost. Verify with `auditctl -l` that it loaded, then generate the event and check
> it appears in `ausearch`.

### Tag rules with a key

Always give a rule a key with `-k`. It is the only practical way to find its events
later:

```text
-w /etc/shadow -p wa -k identity
```

```bash
ausearch -k identity
```

## Buffers and backlog

`auditctl -s` reports the kernel audit status and its counters. Recent versions
print more lines (`failure`, `backlog_wait_time`, ...) than this example:

```text
# auditctl -s
enabled 1
flag 1
pid 430
rate_limit 0
backlog_limit 320
lost 0
backlog 0
```

The two numbers worth watching:

- **`backlog`** — events queued but not yet written. It should stay well below
  `backlog_limit`.
- **`lost`** — events that could not be processed at all. On a healthy system this
  should be zero, or very close to it.

If `lost` is climbing, raise the backlog limit:

```text
-b 8192
```

Bigger buffers cost memory. On most machines that is a cheap trade for not dropping
audit events, but it is a trade, not a free win — and a larger buffer hides the
underlying problem, which is usually too many rules.

`--backlog_wait_time` controls what the kernel does when the queue is full: wait
(slowing the offending process) or drop. Waiting is the safer choice for compliance
and the riskier one for availability.

## Watching directories: `path` versus `dir`

Two ways to monitor directory contents:

- **`dir`** — the directory and everything beneath it, recursively.
- **`path`** — that path only.

If you do not need subdirectories, use `path`. It is a small change that can remove
a large amount of pointless logging on a deep tree.

## Restarting auditd

```bash
service auditd restart
```

> [!warning] `systemctl restart auditd` does not work on RHEL
> On RHEL and its derivatives, `auditd.service` is shipped with
> `RefuseManualStop=yes`, so systemd rejects the request:
>
> ```text
> Failed to restart auditd.service: Operation refused, unit auditd.service may be
> requested by dependency only (it is configured to refuse manual start/stop).
> ```
>
> This is deliberate — the audit daemon is not meant to be stoppable by an operator
> who has already been recorded doing something. Use the `service` wrapper. It runs
> `/usr/libexec/initscripts/legacy-actions/auditd/restart`, which sends the daemon
> a stop signal with `auditctl --signal stop`, then runs `systemctl start auditd`.
> Note that reloading *rules* does not need a restart at all: `augenrules --load`
> is enough.
>
> openSUSE does not set `RefuseManualStop`: there, `systemctl restart auditd` works.

## Making the rule set immutable

The last line of a hardened rule set is usually:

```text
-e 2
```

`-e 2` locks the configuration until the next reboot: rules can no longer be added,
removed or changed, even by root. This is a CIS requirement and it does exactly what
it says — if you get the rules wrong, you are rebooting to fix them. Set it only
once the rest is verified.
